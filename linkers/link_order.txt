# linkers/link_order.txt -- the NATURAL link order of NFS4.EXE / FRONT.BIN (Route A).
#
# tools/gen_natural_ld.py turns this into build/full_link/nfs4_natural.ld; tools/full_link.py links
# with it.  Nothing here is an address: every input section is placed right after the previous
# one, so addresses follow from this order and from the object sizes, exactly like the original
# SN link (game objects in the order of the link script, library members in the order the linker
# pulled them in).  Edit a source and everything behind it moves; add an object and list it here.
#
# Line format:   <output section>  <source>  <input section>  [attributes]
#   <source>         recon/... source file; its object is build/<source>.o
#   pad=16           the section's size is rounded up to 16 bytes, measured from its own start
#                    (Sony library members: PsyQ's assembler pads every section to 16)
#   align=N          the section starts on an N-byte boundary (default: 4 in [main], 8 in [front])
#   tail=N           N zero bytes follow the section (bytes of the original object no source owns)
#
# [main]  = NFS4.EXE: text group .rdata .text .data .sdata at 0x80010000 (bigBuf, the front-end
#           overlay's reservation, comes first), then the bss group .sbss .bss.
# [front] = FRONT.BIN: the overlay linked over bigBuf at 0x80010000 (front.rdata front.text
#           front.data front.bss); SN aligned each object's chunk to 8 (`section.8 front.*`).
# Everything ending in .strip (functions retail's /strip link removed) or _legacy is discarded.
